## `LvsService`

### Methods

| Method | Returns | Description |
|---|---|---|
| `checkAccess()` | `Future<bool>` | Whether the account may use the LVS: `true` when the LVS answers the root of its left tree (`POST /?module=LVS&file=treeBuilder`, `id` `0`: the classes the account may see, no pupil), `false` when it refuses it (`SmartschoolLvsAccessDeniedError`). `true` also for a root that lists no class: `checkAccessDetails()` tells how many it lists. Any other failure is thrown. |
| `checkAccessDetails()` | `Future<LvsAccess>` | The same read as `checkAccess()`, with the number of classes the root lists (#184): `LvsAccess`: `granted` (`false` for a refusal), `classCount` (the root's nodes of type `class`, not the LVS's other nodes there; `0` when not granted). Granted with `0` classes: the account may open the LVS but sees no class, so no pupil. Counts only: no class name, no ID. Any other failure is thrown. |
| `searchPupils(text)` | `Future<List<LvsPupilMatch>>` | The pupils whose name matches `text`, in the LVS's order (`GET /LVS/Spotlight?searchVal=<text>`); empty when none does. `LvsPupilMatch`: `pupilId`, `classId`, `name` (plain text: the LVS's `foundName` without the markup that highlights the match), `className`. The classes the search also finds are left out. A blank `text` is an `ArgumentError`, before anything is sent. |
| `getPupilFile({pupilId, classId, withTodayStatus = true})` | `Future<LvsPupilFile>` | The overview of a pupil's file: `GET /LVS/Spotlight/<pupilId>?classID=<classId>`, then today's status (`POST /LVS/Pupilxhr/getStatusInfo` with `pupilID`). With `withTodayStatus: false`, the file only, one request: for an app that needs the sections or `noteCategories` and not the pupil's attendance today; `todayStatus` is then `LvsTodayStatus.none`, not read (#186). See *Models*. An ID that is not positive is an `ArgumentError`, before anything is sent. |
| `getNotes({pupilId, classId, categoryId, schoolYear})` | `Future<List<LvsNote>>` | The notes of a category of the pupil's file, its own (a sub-category's by its own ID, #180), in the LVS's order; only those of `schoolYear` (an `LvsSchoolYear`, the current school year when not given), empty when it holds none. `LvsPupilFile.noteCategories` lists the categories. One request to the LVS's XML dispatcher (`POST /?module=LVS&file=dispatcher`, the command `lvs_cats/getUserCatItems` with `catID`, `userID`, `toolbarType`, `syRange`, `groupID`, `toolbarSide`; answered with `renderPupilNotes`) (#161). An ID that is not positive, or a school year that ends before it starts, is an `ArgumentError`, before anything is sent. |
| `getAllNotes({pupilId, classId, schoolYear})` | `Future<List<LvsNote>>` | All notes of the pupil's file, of every category, in the order of the LVS's "all items" view (its `dates`); only those of `schoolYear`, empty when there are none. The dispatcher's `lvs_pupils/getUserData` (`viewAllFilter` `[]`, `filterData` `0`, as the web client opens the view; answered with `renderPupilAllNotes`, whose reports, absences and other items are left out) (#161). |
| `getResultsConfiguration({pupilId, classId})` | `Future<LvsResultsConfiguration>` | What the results app may show the account for the pupil (#162): `GET /LVS/Results/getConfiguration?pupilId&groupId` (`groupId` is the class), `{capabilities: {canUserSeeAll, canUserSeeSchoolyear}}`. |
| `getResultsPeriods({pupilId, classId, schoolYear})` | `Future<List<LvsResultsPeriod>>` | The periods of the pupil's results in `schoolYear` (the current one when not given), in the LVS's order: `GET /LVS/Results/getperiods` with `pupilId`, `groupId`, `startDate`, `endDate` (#162). |
| `getResultsCourses({pupilId, classId, schoolYear})` | `Future<List<LvsResultsCourse>>` | The courses of the pupil's results: `GET /LVS/Results/getcourses`, as above (#162). |
| `getEvaluations({pupilId, classId, courseIds, periodIds, pageNumber, itemsOnPage, schoolYear})` | `Future<LvsEvaluationPage>` | One page (from 1; 100 per page by default) of the pupil's evaluations with their scores, of the courses and periods given (all when empty), in the LVS's order: `GET /LVS/Results/getevaluationsofuser` with `pageNumber`, `itemsOnPage`, `courseIds` / `periodIds` (sorted, comma-separated, left out when empty) and the school year (#162). `mayHaveMore` tells whether the page is full. |
| `getAllEvaluations({pupilId, classId, courseIds, periodIds, itemsOnPage, maxPages, schoolYear})` | `Future<LvsEvaluationList>` | The evaluations page after page until one is not full, or `maxPages` (10) pages were read: `isComplete` is `false` when the cap stopped a full page. An evaluation that comes again is kept once; a page of only the evaluations before it (the LVS does not page) is a `SmartschoolLvsError`; a page with more than `itemsOnPage` is all of them (#162). |
| `getFeedback({pupilId, classId, schoolYear})` | `Future<List<LvsFeedback>>` | The feedback on the pupil's results, in the LVS's order: remarks on reports (of the class council, or per course) and teachers' feedback on evaluations and on a project's goals, with attachments as metadata: `GET /LVS/Results/getfeedback` (#162). |
| `getReports({pupilId, classId, schoolYear})` | `Future<List<LvsReport>>` | The pupil's reports, metadata only (no download): `GET /LVS/Results/getreports` (#162). |
| `getSupportPlanPeriods({pupilId, classId})` | `Future<List<LvsPlanPeriod>>` | The periods of the support plans, in the LVS's order; empty when there are none (#163). |
| `getSupportPlan({pupilId, classId, periodId})` | `Future<LvsSupportPlan>` | The pupil's individual plan ("IHP") in a period (the current one when not given), its `status`: `plan`, `noPlan` or `noPeriod` (#163). |
| `getProfileSketch({pupilId, classId, periodId})` | `Future<LvsProfileSketch>` | The pupil's profile sketch in a period; `hasSketch` is `false` when there is none (#163). |
| `getAbsences({pupilId, classId})` | `Future<LvsAbsences>` | The pupil's absences, per school year: `POST /LVS/Pupilpresences` with `pupilID`, `groupID` (#164). On a `500`, the read of the pupil's file without today's status, to tell a pupil the LVS does not know (#190). |

- **Only reads, by an allowlist.** The LVS has writes right next to its reads, some on the same URL (`PUT /LVS/Message`, `PUT /LVS/Watch`, `setLastPupil`, which the web client sends for every pupil it shows, the "viewed" flags, the edit locks, every `save*`). The service sends only its reads, each on an explicit list (method, path, query and form fields), and refuses any other request before it is sent (`SmartschoolLvsRequestNotAllowedError`). Reading a pupil's file through the library does not make it the last pupil the account viewed, and marks nothing as seen.
- **No page load.** The reads answer straight after a login: the LVS page (some 300 KB) is not loaded first (seen live, 2026-10-21).
- **A pupil the LVS does not know** in that class: the LVS does not refuse it, it answers with its school's sections (none holding anything) and a placeholder pupil whose class is `null` (seen live for a made-up ID). `getPupilFile` throws a `SmartschoolLvsPupilNotFoundError` for it, and does not read today's status (which the LVS answered with a `500` for that ID). The absences have no such answer: the LVS answered them for a made-up ID with a `500` and Smartschool's error page, as it can answer any read it fails, so on a `500` `getAbsences` reads the pupil's file (without today's status) and throws the same `SmartschoolLvsPupilNotFoundError` for the placeholder pupil; for a pupil the LVS knows, or when that read fails, the `500` stands, a plain `SmartschoolLvsError` (#190).
- **Notes** (#161). The categories are the school's own: the library lists them (`noteCategories`) and reads the notes of one by its ID, or all of them. A note's fields carry what it says, each with its label and the text the web client shows (`LvsNoteField.value`: a text, a rich text as plain text with its HTML in `html`, the chosen option(s), the day of a date in Belgian time, attachment names); a type the library does not know is kept with its raw values. Attachments are metadata only (no download). Confidential notes come marked (`isConfidential`), not left out: the LVS decides which ones the account receives. The default period is the current school year (1 September to 31 August, Belgian time); the LVS page itself sends the period of the user's own settings. The LVS does not apply the period reliably, so the library keeps the notes of it (`LvsSchoolYear.includesNote`: by their school year label, by their date without one) (#180). The library sends no "viewed" flag and no edit lock (`changeItemViewStatus`, `setItemViewState`, `checkItemEditor` are refused by the allowlist).
- **Unknown IDs** for the notes: the LVS answers a pupil it does not know with its placeholder pupil (`SmartschoolLvsPupilNotFoundError`) and a category it does not know without the category (`SmartschoolLvsCategoryNotFoundError`), both seen live for made-up IDs. For `getAllNotes` it sends no data at all, the same as for a pupil without notes: an empty list (`getPupilFile` tells the two apart).
- **Results** (#162). The pupil's file shows its "Resultaten" section (type `results`) with the results app pupils and parents see, embedded for one pupil: the library sends that app's GETs (`/LVS/Results/*`, with `pupilId` and `groupId`, the class), so a teacher reads the pupil's results in **every** course, not only in their own gradebooks. Not its export (`exportgoals`), which the allowlist refuses. Scores are kept as the LVS gives them (`LvsScore`: `type`, `value`, `percentage`, `description`, `color`): a score in points comes as a percentage with the points as the web client shows them ("7/10"); the library computes no averages. Reports and attachments are metadata only (their `downloadUrl` is kept, nothing is downloaded). A `403` is a `SmartschoolLvsAccessDeniedError` (the results app's "no access"), never an empty list; the reads send the app's `X-Requested-With` and JSON `Content-Type` headers (#175); a `500` is a `SmartschoolLvsError`. The shapes come from the results app's JavaScript; a real pupil's answers, and whether the LVS pages the evaluations (the app itself asks for one page of 9999), are the developer's capture step (#168). A school whose file shows the older `skore` section instead is not covered.
- **Support plans** (#163). One POST each to the LVS's JSON dispatchers (`jqDispatcher_hp`: `getIHP`, `getProfielSchets`; `jqDispatcher_settings`: `getLVSspecificTitles`), the live plan only (`exportID` 0); the edit flow's calls (`getIHPondersteuningsnood`, `getOD_doelstellingen`, `checkSyntheseEditor`, every `save*`/`set*`) are refused by the allowlist. A school without support plans has no section of their type in the file (`LvsPupilFile.supportPlanSections`); a class without their structure gets `noPeriod` (seen live for a made-up class). The evaluation of the plan, its report and its versions are not read (#170).
- **Not captured**: what the LVS answers a teacher without LVS rights, a pupil account, and a teacher for a pupil they may not see; a real pupil's notes (their shapes come from the LVS's JavaScript, with the envelope and the first parts of the answers seen live for made-up IDs); and whether the LVS takes notes as seen by the account when they are read (their `isNew`). These are the developer's capture step (#168). The service takes a `403` and a redirect to Smartschool's start page for a refusal; any other answer it cannot read is a `SmartschoolLvsError`, never an empty result.
- **Privacy.** The models print counts only (`toString()`); the errors never carry a name, a text or an ID of an answer in their message. When Smartschool refuses the session for a search, or the client is disposed during one, the search text is left out of the error's message (`searchVal=<searchVal>`).

### Errors

- `SmartschoolLvsError` — the LVS answered with something the service cannot use: another status than `200` (in `statusCode`), an HTML page, invalid JSON or XML (the parser's error in `cause`, which `toString()` does not print), a dispatcher `status` other than `ok` (its `message` in `cause`), or an unknown shape. Never an empty result. The session was accepted: signing in again does not help.
- `SmartschoolLvsAccessDeniedError` (a `SmartschoolLvsError`) — the LVS refused the read to the account (`403`, or a redirect to Smartschool's start page).
- `SmartschoolLvsPupilNotFoundError` (a `SmartschoolLvsError`) — `getPupilFile` or `getNotes` got the LVS's placeholder pupil; `getAbsences` got a `500`, and the placeholder pupil for the pupil's file (#190). Carries `pupilId` and `classId`; its message holds neither.
- `SmartschoolLvsCategoryNotFoundError` (a `SmartschoolLvsError`) — `getNotes` got no category: the LVS knows no category of notes of that ID. Carries `pupilId`, `classId` and `categoryId`; its message holds none of them.
- `SmartschoolLvsRequestNotAllowedError` (a `SmartschoolLvsError`) — the service refused to send a request that is not one of its reads (a bug of the library): nothing was sent. Carries the `method` and `path`.
- `SmartschoolSessionExpiredError`, `SmartschoolConnectionError` — as for every service.
